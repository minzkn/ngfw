# 10. 사용자 식별 (USER-ID)

libngfw `identity` 서브시스템. 세션-사용자 바인딩을 정책 매칭과 결합한다(`05` §2/§5).

## 1. 모델

| 개념 | 정의 |
|---|---|
| user | 인증 주체(로컬 DB 또는 외부 디렉터리 프록시) |
| group | 사용자 집합(로컬 정의 + 외부 그룹 매핑) |
| binding | (사용자, IP 주소, 유효기간, 인증 방법, 신뢰도) 튜플 |
| trust | 인증 방법별 신뢰도(정책에서 최소 신뢰도 요구 가능) |

- 바인딩은 IP 기반(동일 IP 복수 사용자: 최근 우선 + 정책 선택). NAT 뒤 다중 사용자는 M4+
  (인증 프록시 경유 트래픽 태깅).
- 바인딩 저장: `ngfwd` 메모리+지속(옵션) → 커널 세션에는 `user_id` 인덱스로 기록(`03` §5.1).

## 2. 인증 방법

| 방법 | 상세 | 상태 |
|---|---|---|
| local | 자체 DB(SHA-512 해시, 솔트), 계정 관리 CLI | M1 |
| RADIUS | 자체 클라이언트(RFC 2865/2866), MS-CHAPv2/PAP, 어트리뷰트→그룹 매핑 | M2 |
| LDAP/AD | 자체 클라이언트(바인드/검색), AD 그룹 SID→로컬 그룹 매핑 | M2 |
| Captive Portal | HTTPS 포탈(WebUI 재사용), 인증 후 IP 바인딩 | M2 |
| Kerberos/SPNEGO | 비목표(M5 검토, AD 환경은 LDAP 인증으로 충족 시) | 후기 |
| SAML/OIDC | 관리 평면 용도만(`11`), 데이터 평면은 포탈 경유 | M4 |

- 인증 서버 플러그인 포인트(신규 방법 추가), `19-plugin-architecture.md` 유형 auth.
- 실패/락아웃 정책: 시도 레이트, 계정 잠금, 감사 로그(`12` §2).

## 3. 바인딩 라이프사이클

1. 인증 성공 → binding 생성(만료: 리스/세션 연동).
2. 커널에 user_id 전파: 기존 세션 재평가(`05` §7), 신규 세션은 세션 생성 시 바인딩 조회.
3. 만료/로그아웃 → 바인딩 제거 + 관련 세션 재평가 이벤트.
4. IP 이동(DHCP 재할당): 만료 우선, 경합 시 최신 인증 우선 + 이벤트.

## 4. 그룹 해석

- 외부 디렉터리 그룹 → 로컬 그룹 ID 매핑 테이블(정책 컴파일 시 사용자 정의 그룹 해석).
- 그룹 변경 시 재평가 이벤트(대규모 시 분할 배치).

## 5. 개인정보/감사

- 사용자 식별자는 로그에서 별칭 처리 옵션(`12` §3). 인증 시도/성공/실패 감사 로그는 변조 방지
  해시 체인(로컬 저널), `18` §5.

## 6. selftest 연계

`ngfw selftest identity`: 로컬 인증/락아웃, RADIUS 서버 시뮬레이터(테스트 자산) 왕복, LDAP
시뮬레이터, 포탈 흐름, 바인딩-세션 재평가. `17` §4.
