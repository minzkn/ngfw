# 18. 보안 하드닝 (Security Hardening)

자체 제품의 보안(공격 표면 축소/자기 방어). 데이터 평면 보안 기능은 `07`, 인증은 `10`.

## 1. 위협 모델 요약

| 자산 | 위협 |
|---|---|
| 관리 평면 | 미인증 접근, 권한 상승, CSRF/스크립트 인젝션(WebUI) |
| 설정/시크릿 | 유출, 변조, 백업 평문 노출 |
| 검사 엔진 | 악성 패킷으로 인한 메모리 손상/DoS |
| 커널 모듈 | genl 악성 요청(권한 없는 유저), 세션 테이블 고갈 |
| 업데이트 | 서명 우회, 다운그레이드 공격 |

## 2. 빌드 하드닝(R02 연계)

- 컴파일: `-fstack-protector-strong`, `-D_FORTIFY_SOURCE=2`, PIE+ASLR, `-fvisibility=hidden`,
  릴리스 LTO(선택). 경고 `-Werror`.
- 런타임 검사 활성 빌드(디버그): ASan/UBSan, selftest에서 일부 케이스는 이 빌드로 실행.
- 커널 모듈: 커널 기본 하드닝 옵션 준수, 모듈 내 동적 할당 실패 경로 전 점검, 사용자 공간
  포인터 접근은 copy_*_user 경유 전수 검사.

## 3. 권한 분리/샌드박스

| 프로세스 | 권한 정책 |
|---|---|
| `ngfw-engine` | 비특권 사용자, seccomp(BPF) 화이트리스트, 랜드락(자기 디렉터리), `CAP_*` 없음 |
| `ngfwd` | 초기 root(CAP_NET_ADMIN/CAP_NET_RAW/CAP_SYS_MODULE 필요 연산만) → 권한 강하, 헬퍼 프로세스가 특권 연산 수행 |
| `ngfw` CLI | 호출자 권한 그대로(unix socket 소유자 검사) |

- seccomp 프로파일은 코드와 함께 관리(버전화), 자동 생성 아님 — 명시적 화이트리스트.
- 파일시스템: 읽기전용 rootfs, 쓰기 가능 영역 최소화(설정/로그 파티션).

## 4. 시크릿/키 관리

- 저장소: 설정 파티션 내 암호화 볼트(AES-GCM, 키는 기기 고유 시크릿+사용자 패스프레이즈 KDF
  (자체 PBKDF2/Argon2i 서브셋)), 파일 권한 0600.
- TLS 서버 키, VPN PSK/키, 자체 CA 키, API 토큰 해시. CA 키 조작은 승인 절차 로그.
- 키 교체(로테이션) 명령 + 이력 기록. 손상 감지(무결성 실패) 시 즉시 경보+서비스 중단 정책.

## 5. 감사 로그 무결성

- 감사 카테고리(설정 변경/인증/키/펌웨어)는 해시 체인 연결(이전 레코드 해시 포함), 원격 syslog
  이중화 권장. 체인 검증 명령 `ngfw audit verify`.

## 6. 업데이트/부팅 신뢰

- 펌웨어 패키지 서명 검증 실패 시 설치 거부(다운그레이드 방지: 버전 단조성 규칙).
- 부트 카운터/롤백(`16` §5), 부트로더 신뢰는 제품 플랫폼 정책(문서화).

## 7. 자체 방어(런타임)

- 관리 평면 레이트 제한/계정 락아웃(`10` §2), WebUI 입력 전수 검증(REST 스키마 기반).
- 엔진 메모리 한도(세션당 버퍼 상한)로 악성 스트림 DoS 제한(`06` §8).
- 커널 모듈은 유저랜드 장애와 독립 동작 보장(`02` §9).

## 8. 취약점 대응 절차

1. 보안 이슈 트래커 별도 분류 → 2. 영향 버전 판정(SemVer, `20`) → 3. 수정+회귀 테스트 →
4. 공지(변경 로그/보안 권고 형식) → 5. selftest에 재발 방지 케이스 추가.

## 9. selftest 연계

`ngfw selftest security`: 권한 강하 동작, seccomp 프로파일 적용/차단, 볼트 암호화 왕복, 패키지
서명 위조 거부, 감사 체인 검증, 관리 평면 레이트 제한. `17` §4.
