# 성능 측정 방법론 조사 (Performance Measurement Methodology)

- 문서 상태: 초안 (research note)
- 작성일: 2026-10-23
- 관련 문서: designs/14 (ngfw 성능 측정 절차, §2 5단계 절차), designs/16 (자체 트래픽 생성기 ngfw-tgen, §3)
- 표기 규칙: 본문은 한국어, 기술용어는 영문 병기. 성능 수치 인용은 P-G 원칙(§5.1)을 적용한다.

## 1. RFC 2544 개념 요약

RFC 2544 "Benchmarking Methodology for Network Interconnect Devices"는 네트워크
장비(L2/L3 스위치, 라우터)의 성능을 재현 가능한 절차로 측정하기 위한 표준
방법론이다. 공식 시험 대상은 이더넷 장비이지만, 측정 원리는 ngfw 성능 측정의
기초 어휘로 널리 쓰인다. 핵심 4개 항목은 다음과 같다.

### 1.1 Throughput (처리량)

- 정의: 프레임 폐기(frame loss)가 발생하지 않는 조건에서 장비가 통과시킬 수
  있는 최대 부하율(offered load).
- 절차: 고정 프레임 크기별로 부하를 단계적으로 올려 일정 시간 동안 송수신
  프레임 수를 비교하고, 폐기율 0%가 유지되는 최대 부하율을 이진 탐색(binary
  search)으로 수렴시킨다.
- 단위: pps(packets per second) 또는 Gbps. 프레임 크기별(64B/1500B 등)로
  별도 기록한다.

### 1.2 Latency (지연)

- 정의: 부하 하에서 입력 프레임의 첫 비트 수신 시각부터 출력 프레임의 마지막
  비트 송출 시각까지의 시간(RFC 2544의 store-and-forward 기준 정의).
- 측정 지점: throughput 수준과 포화점 사이 어느 부하율에서 재느냐에 따라 값이
  크게 달라지므로, 측정 시 부하율 조건을 결과에 명시해야 한다.
- 보고 형식: 단일 값보다는 백분위수 분포(§2.2)로 보고하는 것이 현대적 관행이다.

### 1.3 Frame loss (프레임 손실)

- 정의: 고정 부하율에서 송신 프레임 수 대비 수신 프레임 수의 차이(%).
- 활용: 부하율을 여러 지점에서 측정해 부하-손실 곡선(loss profile)을 만들면,
  장비가 포화에 어떻게 접어드는지(급락형/완만형)를 비교할 수 있다.

### 1.4 Bursting (버스트)

- 정의: 장비의 버퍼링 능력(buffering capacity)을 측정하는 항목. 최소
  inter-frame gap을 유지한 버스트를 인가하고, 폐기 없이 통과되는 프레임 수를 잰다.
- 의미: 평균 부하 기반 처리량만으로는 보이지 않는 순간 과부하 내성과 큐 깊이
  동작을 드러낸다.

RFC 2544는 L2/L3 스위칭 기준 방법론이므로, HTTP/HTTPS/IPS 같은 L7 처리가 있는
ngfw에는 개념만 차용하고 세션 지향 지표(§2.3, §2.4)를 추가로 정의해야 한다.

## 2. 지표 정의 (Metric Definitions)

### 2.1 처리량 (Throughput)

- pps: 초당 처리 패킷 수. 작은 프레임(64B)에서 파싱/포워딩 경로의 한계를
  측정한다.
- Gbps: 초당 처리 비트 수. 큰 프레임(1500B)에서 대역폭 한계를 측정한다.
- 구분 원칙: L3 포워딩 처리량과 L7(HTTP/HTTPS/IPS) 처리량은 별개 지표이며,
  하나의 수치로 합쳐 보고하지 않는다.

### 2.2 지연 (Latency)

- p50: 중앙값(median). 전반적 수준 파악용.
- p99: 상위 1% 꼬리 값. 실사용 체감 품질의 핵심 지표.
- p99.9: 극단 꼬리 값. 스케줄링 지연, 큐잉 이상, GC 스파이크(§3.3) 탐지용.
- 평균(mean)은 보조 지표로만 기록한다(§3.1 함정 참고).

### 2.3 신규 세션/s (New Sessions Per Second)

- 정의: 초당 새로 성립하는 세션 수. 성립 기준(예: TCP 3-way handshake 완료 +
  정책 통과 + NAT 할당)을 측정 보고에 명시한다.
- 반영 경로: 세션 테이블 lookup, 세션 생성/해제, 정책 매칭, 로그 처리 등
  세션 수명주기 초기 경로의 성능을 대표한다.

### 2.4 동시 세션 (Concurrent Sessions)

- 정의: 장비가 동시에 유지하는 활성 세션 수.
- 측정 포인트: 신규 세션/s(§2.3)와 동시 세션은 독립 지표다. 세션 생성은
  빠르지만 유지/타임아웃 관리가 느린 장비도 있으므로 두 지표를 함께 기록한다.

## 3. 측정 함정 (Measurement Pitfalls)

### 3.1 평균만 보기

- 지연 분포는 long-tail이므로 평균은 꼬리를 가린다. p99/p99.9를 함께 기록하지
  않으면 사용자 체감 품질 저하와 이상 동작을 놓친다.

### 3.2 캐시 워밍 (Cache Warming)

- 측정 초기에는 규칙 컴파일 캐시, 흐름 해시 테이블, TLS 세션 캐시 등이
  채워져 있지 않아 실제보다 낮은 수치가 나온다.
- 대응: 워밍업 구간과 측정 구간을 스크립트로 분리하고, 워밍업 조건을 결과에
  기록한다.

### 3.3 GC/워커 지터 (GC/Worker Jitter)

- 사용자 영역 GC, 워커 스레드 재배치, 로그 플러시 등이 주기적 스파이크를
  만든다.
- 원칙: 지터는 제거 대상이 아니라 관측 대상이다. p99 이상 구간에서 재현
  주기와 크기를 기록해 별도 항목으로 보고한다.

### 3.4 트래픽 생성기 자체 병목 (Generator Bottleneck)

- 생성기가 목표 부하를 만들지 못하면 장비 성능이 아니라 생성기 성능을
  측정하게 된다.
- 확인 절차:
  1. 생성기 송신 카운터와 DUT 수신 카운터를 대조한다.
  2. 생성기 패킷 발생 스레드의 CPU 사용률이 포화되지 않았는지 확인한다.
  3. 포화가 관측되면 해당 측정은 무효로 표시하고 재측정한다.

## 4. 트래픽 생성기 요구사항 (Traffic Generator Requirements)

### 4.1 정확한 타임스탬프 (Accurate Timestamping)

- 송수신 프레임의 시각을 최소 커널 수준, 가능하면 하드웨어 타임스탬프로
  기록한다.
- 지연 측정 분해능의 하한은 타임스탬프 오차가 결정하므로, 오차 크기를 측정
  보고에 병기한다.

### 4.2 멀티코어 발생 (Multicore Packet Generation)

- 단일 스레드/단일 NIC 큐로는 고부하(10Gbps급)를 안정적으로 만들 수 없다.
- RX/TX 큐를 코어별로 분리(RSS)하고, 생성 스레드를 코어에 고정(pinning)해
  캐시 지역성과 스케줄 안정성을 확보한다.

### 4.3 클럭 소스 (Clock Source)

- 생성기와 DUT가 서로 다른 클럭을 쓰면 측정 지연에 클럭 오차가 섞인다.
- 완화 방법: (a) 생성기와 DUT를 같은 호스트에서 분리 실행(루프백 또는
  veth/NIC 직결), (b) PTP 동기화, 중 하나를 선택하고 선택 근거를 기록한다.

### 4.4 시나리오 스크립트 (Scenario Scripts)

- 부하 프로파일(프레임 크기, 세션 생성 패턴, 프로토콜 믹스, 지속 시간)을
  재현 가능한 스크립트/설정 파일로 기술한다.
- 수동 조작에 의한 측정은 재현성이 깨지므로 절차에서 제외한다.

## 5. ngfw-tgen 설계 요구사항과 측정 절차 대응표

### 5.1 용어 규칙 (P-G)

- 성능 수치는 designs/14 §2 측정 절차의 산출물만 인용한다. 본 문서를 포함한
  research/design 문서는 자체 수치를 만들지 않는다.

### 5.2 ngfw-tgen 위치

- designs/16 §3에서 정의하는 자체 트래픽 생성기(ngfw-tgen)는 상용 생성기
  의존을 줄이고, ngfw 시나리오 매트릭스(64B/1500B L3, HTTP/HTTPS/IPS)에
  맞춘 재현 가능한 부하 인가를 목적으로 한다.

### 5.3 설계 요구사항 목록

1. 정확한 타임스탬프: 송수신 시각 기록, 하드웨어 타임스탬프 우선 지원(§4.1).
2. 멀티코어 발생: RSS 기반 큐-코어 분리와 스레드 고정(§4.2).
3. 클럭 소스: 단일 박스 측정 모드와 PTP 동기화 모드 지원(§4.3).
4. 시나리오 스크립트: 시나리오 매트릭스 전 항목을 선언적으로 기술(§4.4).
5. 부하 프로파일 제어: 램프업(ramp-up)/스테디(steady)/스텝(step) 인가 지원.
6. 세션 지표 지원: 신규 세션/s와 동시 세션 측정을 위한 세션 상태 추적(§2.3,
   §2.4).
7. 자기진단: 생성기 자체 포화 감지 시 측정 무효 플래그 출력(§3.4).
8. 결과 산출: designs/14 §2 절차 산출물 형식과 호환되는 요약 출력.

### 5.4 측정 절차 5단계 대응표 (designs/14 §2 ↔ ngfw-tgen)

| designs/14 §2 단계 | 측정 목적 | ngfw-tgen 요구사항 대응 |
| --- | --- | --- |
| 1단계: 환경/기준점 준비 | 워밍업, 부하 프로파일 고정 | 시나리오 스크립트(4), 워밍업 구간 분리(§3.2) |
| 2단계: 처리량 측정 | pps/Gbps 최대값 산출 | 멀티코어 발생(2), 부하 프로파일 제어(5) |
| 3단계: 지연 측정 | p50/p99/p99.9 산출 | 정확한 타임스탬프(1), 클럭 소스(3) |
| 4단계: 세션 지표 측정 | 신규 세션/s, 동시 세션 산출 | 세션 상태 추적(6), 세션 시나리오(4) |
| 5단계: 안정성/반복 검증 | 지터·손실 곡선 확인 | 반복 실행 지원(5), 자기진단(7) |

- 위 표의 단계 명칭은 본 문서에서 기능별로 붙인 라벨이며, 실제 단계 명칭은
  designs/14 §2 원문 용어를 따른다.
- 각 단계의 산출물이 ngfw 성능 보고의 유일한 수치 근거가 되며(P-G), 측정
  시나리오는 64B/1500B L3, HTTP/HTTPS/IPS 매트릭스를 기준으로 한다.
